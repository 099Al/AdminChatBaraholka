# ChatAdmin

ChatAdmin - Telegram-бот для администрирования групповых чатов. Он сохраняет входящие сообщения из групп в SQLite и помогает удалять за последнюю неделю сообщения без нужных ключевых слов, а также повторяющиеся сообщения.

## Что делает проект

- Запускает Telegram-бота на `aiogram`.
- Слушает сообщения в группах и супергруппах.
- Сохраняет в SQLite короткий текст сообщения, хеш текста, дату, автора и признак наличия ключевых слов.
- Позволяет пользователю привязать группу командой `/bind`.
- Через меню бота удаляет сообщения за последние 7 дней:
  - `Удалить Сообщения` - удаляет сообщения без ключевых слов.
  - `Удалить Повторы` - удаляет повторяющиеся сообщения, оставляя первое найденное.
  - `Delete Check` - проверяет, есть ли у бота право удалять сообщения в привязанной группе.
- Содержит отдельный Telethon-скрипт для выгрузки истории Telegram-чата в CSV.

Ключевые слова задаются в [src/constants.py](src/constants.py):

```python
KEYWORDS = {"Цена", "Отдаю", "Бесплатно", "Самовывоз"}
```

Сообщение считается защищенным от удаления, если содержит одно из этих слов без учета регистра. Ответы на другие сообщения помечаются отдельным статусом и не попадают в выборку сообщений без ключевых слов.

## Как работает бот

1. При старте бот создает таблицы БД, настраивает меню команд и начинает polling.
2. В группе пользователь пишет `/bind`, чтобы привязать эту группу к своему Telegram ID.
3. Бот сохраняет новые сообщения группы в таблицу `messages`.
4. Когда пользователь нажимает кнопку очистки, бот берет привязанную группу, выбирает сообщения за последние 7 дней и удаляет подходящие сообщения через Telegram Bot API.
5. После успешного удаления запись также удаляется из локальной БД.

Для удаления сообщений бот должен быть администратором группы с правом `Delete messages`.

## Данные

По умолчанию в режиме разработки база создается в:

```text
data/bot.db
```

В production-режиме используется путь:

```text
/app/data/bot.db
```

URL базы можно переопределить переменной окружения `DB_URL`.

Основные таблицы:

- `messages` - сохраненные сообщения групп.
- `user_chat_bindings` - связь пользователя с активной группой, выбранной через `/bind`.

## Переменные окружения

Проект читает настройки из `.env` через `pydantic-settings`.

Минимальный пример:

```env
BOT_TOKEN=telegram_bot_token
ENV=DEV
```

Опционально:

```env
DB_URL=sqlite+aiosqlite:///data/bot.db
```

Для Docker Compose используется файл `.env.prod`.

## Локальный запуск

Проект рассчитан на Python 3.12 и `uv`.

```bash
uv sync
uv run python -m src.run
```

Перед запуском нужно создать `.env` с `BOT_TOKEN`.

## Запуск в Docker

```bash
docker compose -f deploy/docker-compose.yaml up -d --build
```

Контейнер запускает:

```bash
uv run python -m src.run
```

Папка `data` пробрасывается в контейнер как `/app/data`, чтобы SQLite-база сохранялась между перезапусками.

## Миграции

В проекте настроен Alembic:

```bash
alembic upgrade head
```

При обычном запуске бот также вызывает `Base.metadata.create_all`, поэтому таблицы создаются автоматически, если их еще нет.

## Выгрузка истории чата

В [src/method/reader.py](src/method/reader.py) есть отдельный скрипт на `Telethon`, который читает историю Telegram-чата и сохраняет ее в CSV:

```bash
cd src/method
uv run python reader.py
```

Скрипт авторизуется как пользователь Telegram, читает последние сообщения выбранного чата и пишет результат в `history.csv`.

Важно: API-ключи, `.session`-файлы, `.env`, `.env.prod`, `history.csv` и локальную базу данных не стоит коммитить в репозиторий.

## Ограничения и особенности

- Бот работает только с сообщениями, которые видит после запуска и добавления в группу.
- Удаление за неделю основано на локально сохраненных сообщениях, а не на полном чтении истории Telegram.
- Повторы определяются по нормализованному короткому тексту сообщения.
- Telegram может не дать удалить некоторые сообщения, например если они уже удалены или недоступны для удаления. Такие сообщения считаются пропущенными.
